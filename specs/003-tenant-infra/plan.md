## Summary

A Windows PowerShell provisioning script (`Invoke-DarkFactoryProvisioning.ps1`) that idempotently brings a fresh `aiwhisperer.onmicrosoft.com` M365 Business Basic tenant to the state required by all TheDarkFactory365 specs. Uses three official Microsoft PowerShell modules: SharePoint Online Management Shell (App Catalog, CSP), PnP PowerShell (SharePoint site, lists, Teams, permissions, external sharing), and Power Apps Administration PowerShell (default environment URL). Accepts home location as run-time parameters; seeds the `DarkFactory-Settings` list directly with real values. Produces a structured completion report. Microsoft365DSC excluded (YAGNI — one-time personal provisioning does not require drift detection).


**Structure decision**: Modular PowerShell script with one `.psm1` per resource domain. Entry point imports all modules and orchestrates execution. Each module exports exactly one public provisioning function (Single Responsibility). Internal helpers are unexported. This enables isolated Pester unit testing per module without running against a live tenant.

## Implementation Phases

### Phase 1 — Foundation (Day 1)

**Goal**: Entry point scaffold, report module, connection helpers. No live tenant operations yet.

#### 1.1 Project scaffold
- Create `tenant-infra/` directory with `modules/` and `tests/` subdirectories
- Create `Invoke-DarkFactoryProvisioning.ps1` with parameter block (per `contracts/script-interface.md`), `[CmdletBinding(SupportsShouldProcess)]` for `-WhatIf`, module imports, connection orchestration, and completion report output

#### 1.2 Report module (`DarkFactory.Report.psm1`)
- `New-ProvisioningResult -Resource -Status -Detail`: creates `ProvisioningResult` PSCustomObject
- `Write-ProvisioningReport -Results -TenantDomain -AppCatalogUrl -PowerPlatformUrl`: formats color-coded console table (green=Created, grey=AlreadyExists, yellow=Warning, red=Failed), writes `darkfactory-provisioning-report.txt`, outputs exit-code summary
- **Pester test**: assert table format and file contents from a fixture Results array; assert exit code 0/1/2 mapping

#### 1.3 Connection helpers (in entry point)
- `Connect-SPOService -Url "https://aiwhisperer-admin.sharepoint.com"` (SPO Management Shell)
- `Connect-PnPOnline -Url "https://aiwhisperer-admin.sharepoint.com" -Interactive` (PnP PowerShell)
- `Add-PowerAppsAccount` (Power Apps module)
- All three connections established at script start; failure in any → exit before provisioning begins

**Deliverable**: Script runs, prompts for login, exits with empty report (no provisioning yet).

---

### Phase 2 — Tenant-Level Provisioning (Days 1–2)

**Goal**: App Catalog and CSP managed idempotently via SPO Management Shell.

#### 2.1 App Catalog module (`DarkFactory.AppCatalog.psm1`)
- `Invoke-AppCatalogProvisioning -WhatIf`: `Get-PnPTenantAppCatalogUrl` → if absent, `Register-PnPAppCatalogSite -Url "https://aiwhisperer.sharepoint.com/sites/appcatalog" -Owner ... -TimeZoneId 17` → `ProvisioningResult`
- If newly created: Detail includes `"⚠ Wait 30 min before SPFx deployment"`
- **Pester test**: mock `Get-PnPTenantAppCatalogUrl` returning `$null` → assert `Register-PnPAppCatalogSite` called; mock returning URL → assert not called; assert Warning detail when created

#### 2.2 CSP module (`DarkFactory.CSP.psm1`)
- `Invoke-CSPProvisioning -Source -WhatIf`: `Get-SPOContentSecurityPolicy` → exact-match on source string → `Add-SPOContentSecurityPolicy -Source $Source` if absent → `ProvisioningResult`
- Separately: check `(Get-PnPTenant).DelayContentSecurityPolicyEnforcement`; if enforcement delayed/disabled → additional `SkippedWithWarning` result noting CSP enforcement is not active and the allowlist entry may have no effect until enforcement is enabled
- **Pester test**: mock policy list with/without target source; assert correct branch; assert Warning when enforcement is off

**Deliverable**: App Catalog and CSP provisioned correctly; re-run produces `AlreadyExists` with zero changes.

---

### Phase 3 — Workload Provisioning (Days 2–3)

**Goal**: DarkFactory SharePoint site, config list, permissions, seed data.

#### 3.1 Site module (`DarkFactory.Site.psm1`)
- `Invoke-SiteProvisioning -SiteUrl -WhatIf`: `Get-PnPSite` existence check → `New-PnPSite -Type TeamSite -Title "DarkFactory" -Alias "DarkFactory"` if absent → wait loop (poll `Get-PnPSite` up to 10 × 15 seconds, max 2.5 min) → `ProvisioningResult`
- `Invoke-ExternalSharingProvisioning -SiteUrl -WhatIf`: check and set `ExternalUserAndGuestSharing` at tenant level (`Set-PnPTenant -SharingCapability`) and site level (`Set-PnPTenantSite -Sharing`); enable B2B integration (`Set-PnPTenant -EnableAzureADB2BIntegration $true`); produce `AlreadyCorrect` if already set

#### 3.2 List module (`DarkFactory.List.psm1`)
- `Invoke-ListProvisioning -SiteUrl -WhatIf`: `Get-PnPList -Identity "DarkFactory-Settings"` check → `New-PnPList -Title "DarkFactory-Settings" -Template GenericList` → `Add-PnPField` for DFValue (Text), DFDescription (Note), DFCategory (Choice: Weather/Alerts/General)
- `Invoke-ListPermissionsProvisioning -SiteUrl -WhatIf`: check `$list.HasUniqueRoleAssignments` → if `$false`: `Set-PnPList -BreakRoleInheritance -CopyRoleAssignments $false` → `Set-PnPListPermission` for Owners (Full Control), Members (Read), Visitors (Read); if `$true`: `AlreadyExists`
- `Invoke-ConfigSeedProvisioning -SiteUrl -SeedEntries -WhatIf`: for each `ConfigSeedEntry`, CAML query for existing item by Title → `Add-PnPListItem` only if not found; one `ProvisioningResult` per key
- **Pester tests**: list existence guard; `HasUniqueRoleAssignments` guard; seed skip-if-exists; column creation

**Deliverable**: DarkFactory site live, `DarkFactory-Settings` list with all 8 Spec 001 keys seeded from parameters, permissions correct.

---

### Phase 4 — Teams and Guest Access (Day 3)

**Goal**: DarkFactory Teams team, General channel, guest Visitor grants, Power Platform URL.

#### 4.1 Teams module (`DarkFactory.Teams.psm1`)
- `Invoke-TeamsProvisioning -WhatIf`: `Get-PnPTeamsTeam | Where-Object DisplayName -eq "DarkFactory"` → `New-PnPTeamsTeam -DisplayName "DarkFactory" -Visibility Private` if absent (no `-Members`/`-Owners` on creation) → `Start-Sleep 60` → `Get-PnPTeamsChannel` check for General → `New-PnPTeamsChannel -DisplayName "General"` only if absent; returns results for team and channel separately

#### 4.2 Access module (`DarkFactory.Access.psm1`)
- `Invoke-GuestAccessProvisioning -SiteUrl -GuestEmails -WhatIf`: for each email → `Get-PnPUser -Identity $email` existence check → `Add-PnPUser -LoginName $email -Group "DarkFactory Visitors"` if found; `SkippedWithWarning` with "Account not found — invite first" if not

#### 4.3 Power Platform module (`DarkFactory.PowerPlatform.psm1`)
- `Get-PowerPlatformEnvironmentUrl`: `Get-AdminPowerAppEnvironment -Default` → extract `Properties.LinkedEnvironmentMetadata.InstanceUrl` → `ProvisioningResult` with `AlreadyExists` status and URL in Detail

**Deliverable**: Teams team visible in client; guest accounts granted site Visitor access; Power Platform URL recorded in completion report.

---

### Phase 5 — Testing and Polish (Day 4)

**Goal**: Pester tests confirm idempotency and edge cases; documentation finalized.

#### 5.1 Idempotency integration test
- Mock all `Get-` cmdlets to return "already provisioned" state
- Assert: all results are `AlreadyExists`/`AlreadyCorrect`; exit code 0; no write cmdlets (`New-`, `Add-`, `Set-`) called

#### 5.2 Parameter validation and `-WhatIf` tests
- Assert: latitude `-91` → parameter validation error before connections open
- Assert: invalid email format in `GuestEmails` → parameter validation error
- Assert: `-WhatIf` → all provisioning functions called but `ShouldProcess` returns false; no writes; console shows `[WhatIf]` prefix

#### 5.3 Edge case tests
- Assert: App Catalog exists at returned URL → `AlreadyExists`, `Register-PnPAppCatalogSite` not called
- Assert: `HasUniqueRoleAssignments = $true` → `BreakRoleInheritance` not called
- Assert: CSP exact-match (`api.open-meteo.com` does not match `not-api.open-meteo.com`)
- Assert: Teams team wait loop retries correctly when initial `Get-PnPTeamsTeam` returns empty

#### 5.4 Documentation finalization
- `quickstart.md` verified: parameter names match final script exactly
- `contracts/script-interface.md` example output updated to match actual report format

**Deliverable**: All Pester tests pass. Script is idempotent on second run in all tested paths. Documentation accurate.

## Key Design Decisions (SOLID/DRY reference)

| Decision | Principle | Rationale |
|---|---|---|
| One module per resource domain | S (Single Responsibility) | Each module testable and replaceable independently |
| `[CmdletBinding(SupportsShouldProcess)]` on all provisioning functions | O (Open/Closed) | `-WhatIf` flows through without modifying function logic |
| `ProvisioningResult` PSCustomObject as universal return type | L (Liskov) | All modules return same shape; orchestrator handles them uniformly |
| Each module exports exactly one public `Invoke-*` function | Interface Segregation | Consumers depend only on the function they need |
| Connections established at entry point, passed to modules | D (Dependency Inversion) | Modules never create connections; mockable in Pester tests |
| `HasUniqueRoleAssignments` guard before `BreakRoleInheritance` | DRY | One guard prevents silent permission destruction on re-run |
| Microsoft365DSC excluded | YAGNI | Drift detection unjustified for one-time personal provisioning |
| Report as collected array, formatted once at end | DRY | Single formatting function; same output on console and file |
