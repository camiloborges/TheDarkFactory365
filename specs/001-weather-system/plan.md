## Summary

A Microsoft SharePoint Framework (SPFx 1.22) web part built with React 17 and Fluent UI v8, deployed tenant-wide via the App Catalog and surfaced as a native SharePoint tab inside the DarkFactory Microsoft Teams team. It fetches current weather conditions and a 3-day forecast from Open-Meteo (free, no API key) and reads home location from a SharePoint list config store. Dark Factory visual identity applied as scoped SCSS overrides on Fluent UI components. Auto-refreshes every 5 minutes using the Page Visibility API; always shows last-known data with a staleness warning after 30 minutes. WCAG 2.1 AA compliant.

## Implementation Phases

### Phase 1 — Foundation (Days 1–2)

**Goal**: Runnable web part scaffold with working config read and DisplayState skeleton.

#### 1.1 Scaffold and configure

- Run `yo @microsoft/sharepoint` with React + Teams enabled
- Install `@fluentui/react@8`, jest, testing-library, jest-axe, jest-fetch-mock
- Configure `serve.json` to point at the DarkFactory team site workbench
- Set up `tsconfig.json` paths for clean imports (`@models/*`, `@services/*`, etc.)

#### 1.2 Models and contracts

- Create all models from `data-model.md` (interfaces only — no logic)
- Create `DisplayState` enum
- No tests needed for pure interfaces

#### 1.3 ConfigService

- Reads all required config keys from `DarkFactory-Settings` list in parallel
- Validates required keys (see `contracts/sharepoint-config-list.md`)
- Returns `IWeatherConfig` or throws a typed `ConfigError` with missing key names
- **Unit test**: mock `spHttpClient`; assert correct `IWeatherConfig` assembled; assert `ConfigError` thrown on missing keys

#### 1.4 Root component skeleton

- `DarkFactoryWeather.tsx` owns `displayState`, `weatherData`, `lastUpdated`
- On mount: set `DisplayState.Loading` → call `ConfigService` → on success call `WeatherService` → set `DisplayState.Live`
- On `ConfigError`: set `DisplayState.SetupRequired` with missing key list
- Render the correct child based on `displayState` — no data logic in JSX
- Dark Factory palette tokens in `DarkFactoryWeather.module.scss` (colour variables only)

**Deliverable**: Web part loads in workbench; shows `Loading` then `SetupRequired` (config list not yet populated).

### Phase 2 — Weather Data (Days 3–4)

**Goal**: Live weather data displayed with correct mapping.

#### 2.1 WeatherCodeMapper

- Static lookup table: WMO code → `{ label: string; isRain: boolean }`
- Exported as a pure function `getWeatherCode(code: number)`
- **Unit test**: all rain codes return `isRain: true`; code 0 returns `isRain: false`; unknown code returns safe default

#### 2.2 ForecastPeriodMapper

- Pure function: `mapTodayPeriods(hourly: OpenMeteoHourly, now: Date): IForecastPeriod[]`
- Period boundaries: Morning 06–11, Afternoon 12–17, Evening 18–20, Tonight 21–23
- Filters out periods where all hours have passed
- Aggregates temperature (average), condition (max WMO severity), precipitation (sum)
- **Unit test**: given hourly data for a full day, at 14:00 returns only Afternoon/Evening/Tonight; at 22:00 returns only Tonight

#### 2.3 WeatherService

- `fetch(config: IWeatherConfig): Promise<{ reading: IWeatherReading; periods: IForecastPeriod[]; forecastDays: IForecastPeriod[] }>`
- Builds Open-Meteo URL from config (see `contracts/open-meteo-api.md`)
- Maps response to `IWeatherReading` using `WeatherCodeMapper`
- Maps hourly data to today periods using `ForecastPeriodMapper`
- Maps daily[1..2] to 2-day forecast `IForecastPeriod[]`
- On any error: throws typed `WeatherFetchError`; caller decides display state
- **Unit test**: mock `fetch`; assert correct mapping from fixture response; assert error handling

#### 2.4 CurrentConditions component

- Props: `reading: IWeatherReading`
- Renders: temperature (large), feels-like, condition label, wind speed + direction (compass label), humidity, UV index (hidden if null), sunrise, sunset
- Fluent UI `Stack` and `Text` components; Dark Factory SCSS overrides
- Rain condition: apply `accent` electric blue colour to condition label
- **Accessibility**: all data points have `aria-label` with units spelled out (e.g., "22 degrees Celsius")

#### 2.5 ForecastStrip component

- Props: `periods: IForecastPeriod[]`
- Renders today's remaining grouped periods as horizontal cards (Morning / Afternoon / Evening / Tonight)
- Rain periods: accent electric blue border on card
- Hidden if `periods.length === 0`

#### 2.6 ForecastDays component

- Props: `days: IForecastPeriod[]`
- Renders 2 day cards: day name, high/low, condition icon
- Rain days: same visual distinction as ForecastStrip

**Deliverable**: Full weather data visible in workbench with correct Dark Factory styling.

### Phase 3 — Reliability and Polish (Days 5–6)

**Goal**: Auto-refresh, caching, staleness, and all display states complete.

#### 3.1 CacheService

- `save(data: WeatherReading, periods, forecastDays): void` — localStorage with scoped key + timestamp
- `load(): CachedWeatherData | null` — returns null if localStorage unavailable
- `isStale(timestamp: Date): boolean` — true if older than 30 minutes
- Catches `QuotaExceededError` silently; falls back to no-cache
- **Unit test**: save → load round-trip; isStale returns correct value; QuotaExceededError handled gracefully

#### 3.2 useAutoRefresh hook

- Signature: `useAutoRefresh(onRefresh: () => Promise<void>, intervalMs: number): void`
- On mount: fetch immediately, start interval
- On `visibilitychange` hidden: clear interval
- On `visibilitychange` visible: fetch immediately, restart interval
- On unmount: clear interval, remove listener
- **Unit test**: mock `document.visibilityState`; assert interval paused/resumed correctly

#### 3.3 StatusBar component

- Props: `state: DisplayState; lastUpdated: Date | null`
- Renders a subtle bar at the bottom of the web part
- `Live`: small "Updated {time}" in secondary text colour
- `Cached` (< 30 min): same as Live
- `Stale` (≥ 30 min): amber warning indicator + "Data may be outdated — last updated {time}"
- `SetupRequired`: amber banner with key names and link to config list
- `Error`: error message (first-load only)

#### 3.4 Teams context detection

- In `DarkFactoryWeatherWebPart.ts` `onInit()`: check `this.context.sdks.microsoftTeams`
- Pass `isTeams: boolean` prop to root component
- Root component uses this only for minor layout adjustment (e.g., padding) — no functional difference

#### 3.5 Responsive layout

- `DarkFactoryWeather.module.scss`: media query at 768px breakpoint
- Below 768px: ForecastStrip periods stack vertically; ForecastDays stack vertically
- Above 768px: horizontal card row

#### 3.6 Accessibility audit

- Run `jest-axe` against all components in test suite
- Verify keyboard tab order: StatusBar → CurrentConditions → ForecastStrip → ForecastDays
- Verify all colour combinations against WCAG 2.1 AA (see contrast table in spec)

**Deliverable**: Fully functional, accessible, styled web part ready for deployment.

## Key Design Decisions (SOLID/DRY reference)

| Decision | Principle | Rationale |
|---|---|---|
| Services are plain TS classes, injected at web part root | D (Dependency Inversion) | Components have no knowledge of how data is fetched |
| `WeatherCodeMapper` is a pure lookup function | S (Single Responsibility) + DRY | One place to change if WMO codes change; no duplication |
| `ForecastPeriodMapper` is a pure function, not a class | S + DRY | No state, easy to test, no coupling |
| `DisplayState` enum drives all rendering decisions | O (Open/Closed) | New states added without touching existing render branches |
| `CacheService` handles QuotaExceededError silently | S | Caching is its own responsibility; components never see storage errors |
| No multi-provider weather abstraction | YAGNI | v1 only needs Open-Meteo; adding abstraction now would violate DRY by requiring an interface with one implementation |
| All Dark Factory colours defined once in `DarkFactoryWeather.module.scss` | DRY | One change updates the whole web part |
