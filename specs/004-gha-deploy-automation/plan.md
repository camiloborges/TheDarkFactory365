## Summary

Two GitHub Actions workflow files automate the full TheDarkFactory365 deployment pipeline. `ci-spfx.yml` validates every pull request touching the SPFx web part (build + tests). `deploy.yml` deploys all three specs on merge to `main` or manual trigger — SPFx to the SharePoint App Catalog (via PnP.PowerShell), the Logic App workflow definition to Azure (via az CLI with OIDC), and the SharePoint seed script idempotently. A single Entra service principal is used for all operations: OIDC federated credentials for Azure CLI, certificate-based auth for PnP.PowerShell. No credentials appear in committed files; all are stored in GitHub Secrets.

## Technical Context

| Dimension | Value |
|---|---|
| **Workflow language** | GitHub Actions YAML (`.github/workflows/`) |
| **Runtime** | `ubuntu-latest` GitHub-hosted runners |
| **Azure auth** | OIDC via `azure/login@v2` (federated credential on service principal) |
| **SharePoint auth** | PnP.PowerShell v2, certificate (`-CertificateBase64Encoded`) |
| **SPFx deployment** | PnP.PowerShell `Add-PnPApp` + `Publish-PnPApp` |
| **Logic App deployment** | `az logic workflow update --definition @file --parameters @params` |
| **Path filtering** | `dorny/paths-filter@v3` for job-level conditional execution |
| **Artefact store** | GitHub Actions Artefacts (7-day retention), within-run only |
| **Target platform** | `camiloborges/TheDarkFactory365` GitHub repository |
| **Testing** | `jest` unit tests (run in CI job); no test suite for workflow YAML itself |
| **Constraints** | Deployment only from `main` branch; manual gates for Logic App OAuth and enable |

## Implementation Phases

### Phase 1 — CI Workflow (`ci-spfx.yml`)

**Goal**: Every PR touching `src/dark-factory-weather/` gets automatic build validation and test results.

**Trigger**: `pull_request` with `paths: src/dark-factory-weather/**`

**Job: `build-and-test`**:
1. `actions/checkout@v4`
2. `actions/setup-node@v4` with Node.js version matching `src/dark-factory-weather/.nvmrc` or `package.json engines`
3. `npm ci` in `src/dark-factory-weather/`
4. `npm test` — runs Jest test suite; fails workflow on test failure
5. `npm run build` (or `gulp bundle --ship && gulp package-solution --ship`) — produces `.sppkg`
6. `actions/upload-artifact@v4` — uploads `src/dark-factory-weather/sharepoint/solution/*.sppkg` as `spfx-package`, retention 7 days

---

### Phase 2 — Deploy Workflow (`deploy.yml`)

**Goal**: Every merge to `main` deploys changed components; manual trigger deploys everything.

**Triggers**:
```yaml
on:
  push:
    branches: [main]
    paths:
      - 'src/dark-factory-weather/**'
      - 'src/rain-alert/logic-app-definition.json'
      - 'src/rain-alert/deploy/**'
      - 'specs/003-tenant-infra/**'
  workflow_dispatch:
```

**Required permissions** (top-level):
```yaml
permissions:
  id-token: write    # OIDC token exchange for azure/login@v2
  contents: read
```

#### Job 1: `detect-changes`

Runs `dorny/paths-filter@v3` to emit output booleans for each path group. On `workflow_dispatch`, all outputs are forced to `true`.

```yaml
outputs:
  spfx:             steps.filter.outputs.spfx
  logic-app:        steps.filter.outputs.logic-app
  sharepoint-seed:  steps.filter.outputs.sharepoint-seed
```

#### Job 2: `build-spfx`

Condition: `needs.detect-changes.outputs.spfx == 'true' || github.event_name == 'workflow_dispatch'`

Steps:
1. Checkout
2. Setup Node.js
3. `npm ci` in `src/dark-factory-weather/`
4. `npm test` — must pass before build
5. Build production bundle
6. Upload `.sppkg` artefact

#### Job 3: `deploy-spfx`

Condition: same as `build-spfx`
Needs: `build-spfx`

Steps:
1. Checkout
2. Download `spfx-package` artefact
3. Install PnP.PowerShell (pinned version)
4. `Connect-PnPOnline` using `SP_CERT_BASE64` and `AZURE_CLIENT_ID` secrets
5. `Add-PnPApp -Path *.sppkg -Scope Tenant -Overwrite`
6. `Publish-PnPApp -Identity $app.Id -Scope Tenant`
7. Print deployment summary with app version

#### Job 4: `deploy-logic-app`

Condition: `needs.detect-changes.outputs.logic-app == 'true' || github.event_name == 'workflow_dispatch'`
Needs: `detect-changes`

Steps:
1. Checkout
2. `azure/login@v2` — OIDC login (uses `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID` secrets)
3. Query `connectionRuntimeUrl` for SharePoint connection:
   ```bash
   az rest --method get \
     --url "https://management.azure.com/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.Web/connections/$SP_CONN?api-version=2016-06-01" \
     --query "properties.connectionRuntimeUrl" -o tsv
   ```
4. Query `connectionRuntimeUrl` for Teams connection (same pattern)
5. Populate `connection-parameters.json.template` with real values (subscription ID, resource group, connection runtime URLs)
6. `az logic workflow update --resource-group $RG --name $LOGIC_APP --definition @src/rain-alert/logic-app-definition.json --parameters @connection-parameters.json`
7. Print post-deploy reminder (manual gates: authorise connections, enable Logic App)

#### Job 5: `deploy-sharepoint-seed`

Condition: `needs.detect-changes.outputs.sharepoint-seed == 'true' || github.event_name == 'workflow_dispatch'`
Needs: `detect-changes`

Steps:
1. Checkout
2. Install PnP.PowerShell (pinned version)
3. Run `src/rain-alert/deploy/Invoke-AlertSeedData.ps1` with `-SiteUrl ${{ vars.SHAREPOINT_SITE_URL }}` — uses `SP_CERT_BASE64` for auth
4. Print idempotency summary (items added vs skipped)

## Complexity Tracking

No constitution violations. All decisions justified:

| Decision | Added complexity | Justification |
|---|---|---|
| Two auth methods (OIDC + certificate) | Requires federated credential setup AND cert generation | OIDC unavailable natively in PnP.PowerShell without wrapper action; certificate is the supported path. Using OIDC for az CLI avoids storing ANY Azure credentials as secret material. |
| `dorny/paths-filter@v3` dependency | Third-party action | Native GHA path filtering is workflow-level only; job-level conditional execution requires a helper. `dorny/paths-filter` is MIT-licensed, widely used (100M+ runs/month), and has no network egress of secrets. |
